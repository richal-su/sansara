## Цель

Описать целевой экран метрик для владельца продукта и оператора matching.

## Исходные данные и допущения

- `data/raw/technical_architecture.txt`, раздел KPI Dashboard.
- Данные: `data/processed/kpi_dashboard_example.md`.

## Содержание

Пример панели (**не реальные результаты**):

| KPI | Пример |
|---|---:|
| Активных компаний | 315 |
| Активных товаров | 28 400 |
| Закупочных заявок | 1 720 |
| Найдено matches | 740 |
| Match Rate | 43% |
| Match → Deal | 19% |
| Сделок | 141 |
| GMV | 42,8 млн ₽ |
| Выручка | 1,02 млн ₽ |
| Take Rate | 2,4% |
| Recovered Capital | 39,5 млн ₽ |
| Buyer Savings | 7,8 млн ₽ |
| Repeat Rate | 41% |

Рекомендуемые блоки UI:

- Воронка: заявки → matches → офферы → сделки.
- Качество AI: Acceptance Rate, Precision (по мере накопления разметки).
- Экономика: GMV, take rate, средняя экономия покупателя.
- Операции: очередь ручной проверки matching (связь с админкой MVP).

## Ключевые наблюдения

- Пример Match Rate 43% при Match→Deal 19% иллюстрирует, что узкое место может быть не в поиске, а в закрытии сделки — на пилоте это нужно проверить, не считать фактом.

## Принятые решения

- North Star на dashboard: GMV завершённых сделок.

## Обоснование

Единый экран связывает продуктовые и AI-метрики для решений по roadmap.
