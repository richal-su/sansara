## Содержание

### Использованный метод

Вместо выдуманных баллов RICE применена **приоритизация из MVP-документа**: P0 блокирует проверку гипотезы matching и сделок; P1 усиливает удержание и документооборот; P2 — масштаб и автоматизация платежей/логистики.

| Приоритет | Фокус | Ключевые элементы |
|---|---|---|
| P0 | Доказать matching → deal | Ingestion, кабинеты, лента офферов, Match Score, подтверждение сторон, админка, метрики |
| P1 | Efficiency & trust | Аналитика, история, рейтинг, ЭДО |
| P2 | Scale | Mobile, автоплатежи, API ERP, логистика |

### Связь с продуктовой гипотезой

| Гипотеза | Что должно войти в P0 |
|---|---|
| AI находит релевантные совпадения | Нормализация, фильтры, semantic matching, score, оператор |
| Компании готовы закрывать сделки | Оффер с экономией, двустороннее подтверждение, документы, ручная логистика |
| Монетизация возможна | Тариф Start (комиссия 3%), учёт GMV и take rate |

## Ключевые наблюдения

- Для учебного RICE-артефакта нужны оценки команды; в исходных docx их нет.

## Принятые решения

- Официальная очередь MVP = порядок P0-1 … P0-12 в `product_backlog.md`.

## Обоснование

Сначала data + matching + human confirmation — иначе метрики Acceptance Rate и Match→Deal не интерпретируются.
