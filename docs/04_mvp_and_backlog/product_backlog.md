## Содержание

### Пользовательские истории (черновик С5)

**US-1.** Как менеджер снабжения продавца, хочу загрузить остатки из Excel/CSV по пяти категориям пилота, чтобы система могла искать покупателей без публикации всего склада.

**US-2.** Как закупщик, хочу получать AI-офферы по моим заявкам с Match Score и экономией с учётом доставки, чтобы сравнить вариант с обычным поставщиком до заказа.

**US-3.** Как уполномоченный представитель компании (продавец или покупатель), хочу подтвердить или отклонить сделку и получить базовый комплект документов, чтобы закрыть поставку на платформе.

#### Раскрытие US-2

Уточнить: как считать «экономию», если у покупателя нет цены текущего поставщика в выгрузке.

| Критерий приемки | Описание |
|---|---|
| AC-1 | При загрузке заявки с обязательными полями (категория, ключевые характеристики, объём, регион) система показывает оффер или явное «совпадений нет» не дольше согласованного time-to-match на пилоте |
| AC-2 | В карточке оффера видны Match Score, параметры совпадения, оценка логистики и комиссия тарифа Start |
| AC-3 | Действия «Принять / Изменить / Отклонить» сохраняют статус и причину (для обратной связи matching) |

Подзадачи US-2:

1. Собрать карточку оффера и правила расчёта полной стоимости (цена + доставка + комиссия).  
2. Подключить очередь оператора для офферов с Match Score ниже порога автопоказа.

### Функции по ролям (сводка)

**Продавец:** интеграция, чтение остатков, нормализация, излишки, правила, лента офферов, документы, логистика вручную, выплаты, аналитика возврата капитала.

**Покупатель:** интеграция заявок, нормализация потребности, AI-подбор, карточка предложения, резерв/оплата, документы, аналитика экономии.

**Общие:** верификация компаний, статусы сделки, споры, рейтинг/история (сложный рейтинг — не MVP).

### P1 — желательно

- Аналитика (сэкономлено, излишки, оборачиваемость).
- История сделок, рейтинг компаний.
- Интеграция с ЭДО.

### P2 — позже

- Мобильное приложение, автоплатежи, API для ERP, собственная логистика.

### Matching pipeline (ядро)

Ingestion → нормализация → мастер-каталог → жёсткие фильтры → мягкий скоринг → совместимость объёмов → генерация оффера → human-in-the-loop → обратная связь для модели.

## Ключевые наблюдения

- Без качественного matching продукт превращается в обычную площадку.
- Пять категорий усложняют справочники, но повышают шанс ликвидности в одном регионе.

## Принятые решения

- Официальная очередь MVP = порядок P0-1 … P0-12; пакеты для RICE — см. `prioritization_rice.md`.
- Истории US-1…US-3 закрывают критический путь: данные → оффер → сделка.

## Обоснование

Backlog выровнен с MVP scope и технической архитектурой data/matching.
