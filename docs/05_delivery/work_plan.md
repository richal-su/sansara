# Ближайший план работ (после С5)

## Ссылка на визуальный материал

[Открыть доску в Unidraw](#)

## Цель

Зафиксировать ближайший шаг команды 403: что покажем, какой объём доступен и в каком порядке идут пакеты PKG-A → PKG-B → PKG-C.

## Исходные данные и допущения

- Приоритизация RICE: [`../04_mvp_and_backlog/prioritization_rice.md`](../04_mvp_and_backlog/prioritization_rice.md).
- Backlog: [`../04_mvp_and_backlog/product_backlog.md`](../04_mvp_and_backlog/product_backlog.md).
- Исполняемого кода пока нет; результат шага — согласованный прототип сценария и наполненный репозиторий.
- Оценка доступного времени: учебный темп ~ **8–12 чел.-часов в неделю на команду** (ориентир, не таймшит).

## Содержание

### Что покажем в конце шага

Сквозной сценарий «загрузка остатка и заявки → оффер с Match Score → подтверждение обеих сторон» на уровне прототипа/описания экранов и правил matching по **пяти категориям** пилота. Не обещаем работающий production-сервис.

### Когда уточним оценки

После первой пробной нормализации 1–2 реальных (обезличенных) Excel-выгрузок по кабелю и трубам; условие пересмотра — если маппинг полей занимает существенно больше 1 чел.-дня на шаблон.

### План работ

| Порядок / ID | Работа | Оценка и единица | Условие старта | Ведущий | Проверяющий |
|---|---|---|---|---|---|
| 1 / PKG-A | Шаблоны Excel/CSV, онбординг, загрузка остатков и заявок | 5 чел.-дней | Согласованы 5 категорий и обязательные поля | Карпов | Щипунов |
| 2 / PKG-B | Matching, Match Score, лента офферов, карточка матча | 8 чел.-дней | Есть тестовые позиции и заявки из PKG-A | Карпов | Лебединцев |
| 3 / PKG-C | Подтверждение сделки, статусы, комплект документов | 6 чел.-дней | Есть оффер в статусе «на подтверждении» | Щипунов | Мустафин |
| 4 / P0-12 | Уведомления email/Telegram (минимум) | 2 чел.-дня | Есть события оффера и сделки | Мустафин | Щипунов |
| 5 / P0-8 | Админка оператора (очередь проверки) | 3 чел.-дня | Есть офферы ниже порога score | Карпов | Лебединцев |

### Что отложили

- P1-аналитика, ЭДО, рейтинг компаний — после проверки Match→Deal.
- Автоплатежи, escrow, мобильное приложение, API ERP — P2 / горизонт 6–12+ месяцев.
- Расширение категорий за пределы пяти стартовых — после ликвидности пилота.

## Ключевые наблюдения

- RICE ставит PKG-A выше PKG-B, но ценность для пользователя проявляется только когда A и B связаны в одном сценарии.
- Взаимная проверка с другой командой на семинаре 5 ещё не проводилась.

## Принятые решения

- Порядок старта: PKG-A → PKG-B → PKG-C.
- Ответственность по ролям — см. [`../00_course/team.md`](../00_course/team.md).

## Обоснование

План следует из модели RICE и зависимостей критического пути данных → matching → сделка.
