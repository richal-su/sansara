# Семинар 7. AI Product Canvas Sansara

## Цель и источники

Canvas связывает пользовательскую задачу, данные и границы автоматизации. Источники: [архитектура и доска AI](../docs/06_ai_product/ai_solution_concept.md), [исходная техническая концепция](../data/raw/technical_architecture.txt), [backlog](../docs/04_mvp_and_backlog/product_backlog.md). Описанные механизмы являются проектной концепцией.

## Canvas

| Блок | Содержание |
|---|---|
| Пользователь и задача | Закупщик ищет подходящие материалы для заявки; продавец хочет найти покупателя для разрешённого к продаже остатка. Сейчас сопоставление и проверка выполняются вручную в разрозненных системах. |
| Ценность | Покупатель получает подходящее предложение и видит возможную экономию; продавец получает возможность высвободить капитал; платформа предполагает комиссию с завершённой сделки. |
| Данные | Согласованные остатки и потребности из Excel/CSV: категория, название, артикул, характеристики, количество, единицы, цена, состояние и регион; позднее — интеграции 1С/ERP. |
| Target и выход | Кандидаты, пригодные для проверки конкретной заявки; выход — карточка с характеристиками, оценкой совпадения и экономикой, либо сообщение об отсутствии кандидата. Релевантность для оценки устанавливается размеченными примерами. |
| Baseline | Правила и точное сопоставление категории, артикула и критичных характеристик; сравнение с ним позволяет оценить добавленную ценность семантического поиска. |
| AI | Нормализация записей и семантический поиск; LLM может помогать объяснять кандидатов. Точные фильтры и правила сохраняются; конкретная модель не выбрана. |
| Решение | Несовместимые критичные характеристики исключают кандидата до ранжирования. Остальные оцениваются Match Score; при недостаточной уверенности оффер направляется человеку. Оценка не является вероятностью совместимости. |
| Человек и обратная связь | Оператор проверяет спорные результаты; компании подтверждают наличие и решение о сделке. Принятие, отклонение и причина отказа дают материал для последующей оценки и улучшения. |
| Качество и ограничения | Acceptance Rate в сценарии; Precision, Recall и Precision@10 на размеченных данных. Контроль — отсутствие технически несовместимых предложений после проверки. Реальные значения ещё не измерены. |
| Риски | Устаревшие остатки, неполные или ошибочно распознанные характеристики, раскрытие данных и высокая стоимость обработки. Нужны права доступа, ручная проверка и согласованный порядок работы с данными. |

## Архитектура и прототип v1

Вход Excel/CSV → проверка и нормализация → каталог → жёсткие ограничения → точный и семантический поиск → ранжирование → карточка предложения → проверка и подтверждение → обратная связь. Архитектурные варианты и веса модели находятся в [концепции AI](../docs/06_ai_product/ai_solution_concept.md). [Прототип](https://unidraw.io/app/board/beb6977eb0aac20e114b?allow_guest=true) показывает пользовательский сценарий; работающая модель и её тестирование не заявляются.

Распределение ответственности соответствует [составу команды](../docs/00_course/team.md): координация — Лебединцев, сценарии и интерфейс — Щипунов, экономика — Мустафин, архитектура и данные — Карпов.
